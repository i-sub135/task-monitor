# TM-11 — Edit title/description/type di halaman detail task

**Type**: feature
**Status**: Done
**Source**: perintah Iyan lewat DM, 2026-09-28
**Butuh**: TM-5 (halaman detail), TM-6 (transisi status), TM-10 (kalau description udah rich text pas tiket ini digarap; kalau TM-10 belum jalan, edit description tetap teks polos dulu)

## Yang dibikin

Sekarang title dan description task gak bisa diubah setelah dibikin. Tiket ini nambah kemampuan edit, dengan batasan dari Iyan:

- **Cuma bisa diedit kalau status task Request atau Queue.** Begitu masuk In progress/Ready to test/Done/Rejected, title dan description terkunci (konsisten sama alasan transisi cuma maju: begitu masuk kerjaan, spec gak boleh berubah diam-diam).
- **Edit partial**: user bisa ubah title doang, atau description doang — gak wajib isi ulang keduanya sekaligus. Form edit nampilin dua field terpisah (bisa 1 tombol edit per field, atau 1 form dengan 2 field yang masing-masing bisa disubmit sendiri — technical decision pas ngerjain).
- **Validasi sama seperti Task baru**: title wajib, maks 120 karakter; description wajib (gak boleh dikosongin lewat edit).
- **Server yang jadi hakim** (pola yang sama kayak transisi status): guard status Request/Queue dicek ulang di server, bukan cuma disembunyiin di UI kalau status udah berubah pas user lagi buka form edit (race: dua user buka detail bersamaan, satu pindahin status duluan).

## AC

1. Task status Request atau Queue: tombol/aksi edit title dan edit description muncul di halaman detail, bisa dipakai independen (ubah title doang tanpa nyentuh description, dan sebaliknya).
2. Task status In progress, Ready to test, Done, atau Rejected: tombol edit gak muncul, dan endpoint edit (kalau dipanggil langsung) ditolak server dengan pesan jelas — bukan cuma disembunyiin di UI.
3. Title kosong atau > 120 karakter → ditolak, pesan sama kayak Task baru ("Title is required" / "Title must be at most 120 characters").
4. Description kosong → ditolak ("Description is required").
5. Edit sukses langsung kelihatan di halaman detail tanpa reload manual (behavior sama kayak transisi status/reorder yang udah ada).
6. Race: task pindah ke In progress oleh user lain persis sebelum submit edit → submit ditolak server dengan pesan jelas, bukan nyimpen title/description ke task yang udah jalan.
7. `npm run check` dan `npm run build` tetap lulus.

Verifikasi manual (ikutin keputusan v1 TM-9: nol test otomatis, kecuali diputusin lain pas ngerjain).
