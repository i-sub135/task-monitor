# TM-19 — Type baru "support" (bisa langsung Request → Done)

**Type**: feature
**Status**: Backlog
**Source**: perintah Iyan lewat DM, 2026-10-06 ("di create new task, buatin 1 type support. support itu kaya bikinin akun admin dll, nah dia itu statusnya bisa loncat dari request ke done")
**Butuh**: TM-6 (transisi), TM-14 (aturan role), TM-17 (API + enum di kontrak kuli)

## Yang dibikin

Type ketiga selain bug/feature: **support** — kerjaan operasional kayak bikinin akun admin, reset sesuatu, dst.
Bedanya: task support boleh loncat **Request → Done** tanpa lewat Queue / In progress / Ready to test.

Yang kesentuh:
- DB: enum `task_type` + `support` (migration).
- `src/lib/tasks.ts`: type + aturan transisi khusus support.
- Form New task: chip type ke-3 + penjelasan di kotak "Ini bug atau feature?".
- Badge, warna judul kartu (TM terakhir: bug merah, feature ijo), filter Type di board, edit type di detail.
- API v1 + `docs/api.md` + kontrak kuli `SKILL/task-monitor` (enum `type` nambah `support`).

## AC

1. Bisa bikin task type support dari form, API, dan ganti type ke support pas Request/Queue.
2. Task support di Request bisa langsung digeser ke Done (drag + API), sesuai role yang diputusin di bawah.
3. Task bug/feature tetep gak bisa loncat.
4. `npm run check` dan `npm run build` tetap lulus.

## Belum diputusin

1. **Jalur normal tetep boleh?** Support bisa Request → Done *dan* tetep boleh lewat Queue → … → Done kayak biasa, atau cuma Request → Done (+ reject)?
2. **Siapa yang boleh Request → Done buat support?** Usul: developer, QA, admin (marketing tetep gak bisa geser status).
3. **Live:** support Done → Live masih perlu, atau support berhenti di Done (gak ada deploy)?
4. **Tampilan:** warna + ikon badge support. Usul: biru `#578EF5`, ikon LifeBuoy (pelampung) — judul kartu ikut biru.
