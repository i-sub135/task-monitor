# TM-10 — Rich text editor untuk description di form Task baru

**Type**: feature
**Status**: Ready
**Source**: perintah Iyan lewat DM, 2026-09-28
**Butuh**: TM-4 (form Task baru)

## Yang dibikin

Kolom description di `task/new` sekarang textarea polos, disimpan dan ditampilkan sebagai teks (`whitespace-pre-wrap`, auto-escaped, nol HTML). Tiket ini ganti jadi rich text editor dengan minimal: **bullet/numbered list, Bold, Underline, Italic, indent/margin paragraf**. Toolbar kecil di atas area edit, bukan WYSIWYG lengkap.

- **Library editor**: perlu dipilih pas ngerjain. Kandidat: Tiptap (headless, ProseMirror, ada contoh integrasi Svelte) atau editor ringan lain yang jalan di Svelte 5 (runes). Threeshold: bundle size wajar, gak nambah dependency berat kayak nyeret React.
- **Format simpan**: `Task.description` sekarang `String` polos di schema. Kalau editor nyimpen HTML, kolom ini isinya jadi HTML (schema gak berubah, cuma isinya). Alternatif: simpan Markdown lalu di-render jadi HTML pas tampil. Perlu diputusin sebelum ngerjain karena nentuin cara render di detail page dan potensi migrasi data lama (task existing isinya teks polos, tetap harus kebaca normal setelah tiket ini).
- **Sanitasi wajib**: begitu description bisa berisi HTML, itu jadi permukaan stored-XSS (semua role bisa bikin/lihat task). Sanitasi minimal di server sebelum simpan (whitelist tag: `p`, `strong`, `em`, `u`, `ul`, `ol`, `li`, `br`, mungkin `blockquote`), dan render di detail page pakai `{@html}` cuma dari hasil yang udah disaring — nol `{@html}` dari input mentah.
- **Detail page** (`task/[id]/+page.svelte`) ganti dari `<p class="whitespace-pre-wrap">` jadi render HTML yang udah disaring, dengan style list/bold/underline/italic/indent kebaca jelas (rosepine, light theme, `prose`-style kecil kalau Skeleton/Tailwind nyediain).
- **Field lain gak berubah**: title tetap input teks biasa, cuma description yang jadi rich text.

## AC

1. Form Task baru: toolbar minimal (Bold, Italic, Underline, bullet list, numbered list, indent/outdent) di atas area edit description, bisa dipakai dari keyboard shortcut umum (mis. Ctrl/Cmd+B) kalau library-nya dukung bawaan.
2. Description kosong tetap ditolak validasi (aturan sekarang: "Description is required"), termasuk kalau isinya cuma markup kosong (mis. `<p></p>`).
3. Task dibikin dengan list + bold + underline + italic + indent → tersimpan dan tampil identik (list tetap list, bukan teks rata) di halaman detail.
4. Description yang disisipin tag berbahaya (mis. `<script>`, `onerror=`, `<iframe>`) gak pernah nyampe ke output HTML — disaring server, dan hasilnya tetap task yang valid (bukan gagal simpan, kecuali semua isinya cuma markup itu).
5. Task lama (description teks polos, dibuat sebelum tiket ini) tetap kebaca normal di detail page setelah tiket ini jalan (nol migrasi paksa, nol tampilan berantakan).
6. `npm run check` dan `npm run build` tetap lulus dengan dependency baru (kalau nambah library).

Verifikasi manual (ikutin keputusan v1 TM-9: nol test otomatis, kecuali diputusin lain pas ngerjain).

## Belum diputusin

- **Library editor** dan **format simpan** (HTML langsung vs Markdown) — dua keputusan ini saling ngait, sebaiknya diputusin bareng sebelum mulai kode.
- **Cakupan toolbar**: "margin etc-etc" dari perintah Iyan ditafsirin jadi indent/outdent paragraf. Kalau maksudnya beda (mis. alignment kiri/tengah/kanan, ukuran font, warna teks), perlu diklarifikasi sebelum atau pas ngerjain.
- **Style render di detail page**: ngikutin tema rosepine yang ada atau ada kelas baru.
