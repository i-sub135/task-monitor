# TM-15 — Done dibagi dua: Done dan Done (Live), dengan stempel "LIVE" biru

**Type**: feature
**Status**: Ready
**Source**: perintah Iyan lewat DM, 2026-10-01
**Butuh**: TM-5 (board), TM-6 (transisi + history), TM-13 (kolom dibatasi 5 + list)

## Yang dibikin

Sekarang Done itu satu status final. Tiket ini misahin "udah kelar" sama "udah live di produksi". Desain datanya belum ditentuin Iyan; tampilan yang kebayang: task yang udah live dapet **stempel "LIVE" warna biru** di kartunya.

Usulan Kuli Oriental (bisa diralat):

- **Tetap satu kolom Done**, bukan kolom/status baru. Task Done dapet penanda live (kolom `live_at` di `task`, `null` = belum live). Alasan: board udah 6 kolom (di HP jadi 6 tab sempit), kolom ke-7 cuma buat beda tipis bikin makin sesak, dan "live" itu sifat tambahan dari task yang udah Done, bukan langkah kerja baru.
- **Aksi "Mark as live"** di detail task (dan/atau kartu) buat task yang statusnya Done. Tercatat di history (siapa, kapan, catatan opsional mis. versi/tag rilis), jadi gak ilang jejaknya.
- **Tampilan**: kartu yang live dapet stempel "LIVE" — teks tebal kapital, border dobel, agak miring, warna biru dari palet yang udah dipakai (`#2D7495` / `#578EF5`), semi transparan di pojok kanan atas kartu biar judul tetap kebaca. Detail task nunjukin "Live sejak <tanggal>".
- Kolom Done diurutin: yang belum live di atas (masih butuh perhatian), yang live di bawah — atau sesuai keputusan di bawah.

## AC

1. Task Done bisa ditandai live, tercatat di history (siapa + kapan + catatan kalau ada).
2. Kartu task live nampilin stempel "LIVE" biru di `/board`, `/board/list/done`, dan detail task; task Done yang belum live tampil kayak sekarang.
3. Task yang belum Done gak bisa ditandai live (dicek di server, bukan cuma disembunyiin di UI).
4. Task Done lama tetap kebaca normal (default belum live, nol migrasi data paksa).
5. `npm run check` dan `npm run build` tetap lulus.

Verifikasi manual (ikutin keputusan v1 TM-9: nol test otomatis, kecuali diputusin lain pas ngerjain).

## Belum diputusin

- **Model data**: penanda di task Done (usulan di atas) atau status ke-7 `done-live` dengan kolom sendiri di board?
- **Siapa yang boleh mark live**: QA + admin (nyambung sama TM-14), developer juga, atau admin doang?
- **Bisa dibatalin?** Kalau salah tandai / rollback deploy, boleh "unmark live" (tercatat di history) atau final?
- **Catatan pas mark live**: wajib (mis. versi/tag rilis, link deploy) atau opsional?
- **Urutan di kolom Done**: belum-live di atas, atau tetap urut paling baru diubah kayak sekarang?
